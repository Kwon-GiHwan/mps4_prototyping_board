================================================================================
The checker takes NAMED arguments. A bare positional path does NOT work.

  python3 Selftest_measure/check_measure_symbols.py \
      --elf     build_measure_clean/runner_measure.elf \
      --objdump /opt/arm/gcc-arm-none-eabi/bin/arm-none-eabi-objdump \
      --nm      /opt/arm/gcc-arm-none-eabi/bin/arm-none-eabi-nm \
      --profile clean [--advisory]

Or via the Makefile, which supplies all of the above:
  make -f Makefile.measure PROFILE=clean check

--advisory is applied automatically to the WRAPPED profile only.

THREE MODES, ALL EXERCISED ON THE FINAL TREE:
  MODE 1  normal MEASURE_CLEAN                     -> PASS        exit 0
  MODE 2  make ... INJECT_VIOLATION=1  (direct)    -> FAIL        exit 1
          reports: iprintf via run_fixed_inference -> iprintf
  MODE 3  make ... INJECT_INDIRECT=1   (indirect)  -> INCOMPLETE  exit 0
          reports: unexpected indirect calls in run_fixed_inference

MODE 3 is the important honest case: Driver_USART0.Send goes through a
function-pointer struct, references no denylisted symbol, and is INVISIBLE to
any symbol or call-graph check. The checker says so rather than passing.

Known-indirect allowlist: runner_u85_irq_wrapper only. Its indirect call is the
handler chain to the captured original vector, which is required for chaining
and is verified at runtime by npu_vector_hijack_survived. Any indirect call
site outside this allowlist downgrades the verdict to INCOMPLETE.

8. MEASUREMENT CONFIGURATION
================================================================================
completion_wait_mode = BUSY_POLL (1)
  u85.c #defines BUSY_SLEEP, so wait_for_irq() spins instead of __WFI().
  Consequences that must be carried into any comparison: the CPU stays fully
  active during NPU execution; CPU and NPU contend for DDR and interconnect;
  system power differs from an idle-wait implementation; submit->IRQ is a
  polling path, not a sleep latency.
  wait_for_irq() was NOT modified. A WFI variant would be a separate
  experiment configuration, never part of the golden comparison.

TX drain: transmit-empty is not observable on this peripheral, so a fixed drain
delay based on blocking-write completion and assumed hardware residual depth is
applied -- a conservative time bound, not a detected condition.
  cmsdk_apb_uart.h defines the entire STATE register as four bits: RXOR[3],
  TXOR[2], RXBF[1], TXBF[0]. No FIFO level, no FIFO depth, no transmit-idle
  bit, and no CMSDK UART TRM is present in the image. The transmit path depth
  therefore CANNOT be established as at most holding+shift, so 4 resident
  characters are assumed: 4 x 87 us = 348 us. TXBF is NOT used as a drain
  check anywhere.

PMU: NOT IMPLEMENTED THIS MILESTONE. All PMU capability fields return 0 and a
pmu_supported flag of 0. The PMU registers are not read at all. A zero here
means "not implemented" and must never be read as "measured zero".

9. UNVERIFIED -- NO BOARD ACCESS
================================================================================
Everything runtime is unverified. Specifically:

a) ISR-ENTRY INSTRUMENTATION DOES NOT RUN IN THIS BUILD.
   u85.c:329 calls NVIC_SetVector(NPU0_IRQn, &u85_irq_handler) as the FIRST
   statement of test_u85(), and apU85Conv_TEST() calls test_u85(). A wrapper
   installed before the window is overwritten before the NPU is reset or
   submitted to. There is no reachable seam outside u85.c.
   runner_u85_irq_wrapper is implemented exactly to contract (snapshot ->
   chain -> exit timestamp, with a self-capture install guard) and is
   installed, but on this build it will not be reached.
   Expected reported values: npu_vector_hijack_survived = 0, isr_ts_valid = 0,
   isr_entry_ts / isr_exit_ts / npu_qread_at_irq / npu_irq_status_at_irq = 0.
   These are REPORTED as evidence rather than assumed. A measure-private
   u85.c is required to fix this and was deliberately not created.

b) All register-sourced capabilities unread: CPUID, SCB_CCR, MSCR, MPU_CTRL,
   MPU_TYPE, NPU_ID, NPU_CONFIG, SystemCoreClock.

c) rx_bytes_during_measurement is 0-or-1 only: the CMSDK UART has a one-byte
   receive buffer, so the true count of bytes the host sent cannot be
   recovered. rx_overrun_during_measurement is the meaningful signal.

d) unexpected_irq_count is a pending-bit delta, not a true count. An interrupt
   that fired and was serviced inside the window leaves no pending bit.

e) The 348 us drain bound is an assumption about hardware depth, not a
   measurement.

f) The 18 RUNNER_V1_FUNCTIONAL hardware gates have NOT been re-run. The parser,
   CRC range, state table and all pre-existing command handlers are carried
   over unchanged in source, but "unchanged source" is not "re-passed gates".
   CMD_RUN is the one deliberate behavioural change: its ACK is now sent BEFORE
   the measured window and a new unsolicited RUN_COMPLETE (0x31) frame carries
   the result and telemetry afterwards. Any host implementing gate
   coverage for RUN must be updated.

g) FILE LOCATION DEVIATION: runner_measure_main.c lives in Selftest_measure/,
   not Selftest/. Makefile.runner:40 filters out only retarget.c, main.c and
   raw_rx_main.c, so a new main() placed in Selftest/ is compiled into
   RUNNER_V1_FUNCTIONAL and breaks its link -- which would fail the frozen
   gate in section 4. The directory move is what keeps that gate green.
