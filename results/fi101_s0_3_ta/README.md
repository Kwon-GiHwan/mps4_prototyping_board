## Reading (POST_HOC_DESCRIPTIVE)

- Removing the TA limits does **not** remove the gap; it makes it far larger, in all seven models, including the two
  with no gap under profile 1.
- Under profile 2 the NPU counts **fewer** cycles but the CPU sees **more** elapsed time in 6 of 7 models (all but
  rnnoise). NPU-counted cycles therefore do not measure elapsed time, and "profile 2 = full speed" holds only for the
  NPU's own cycle count, not for wall time.
- Consistent with: the NPU's counted clock does not advance during part of the run (gated or stalled), and the share
  of such time depends on the TA settings. Untested; which TA field (e.g. profile 2's `pulse_off` 0, `bwcap` 0) does
  this is not known — the meaning of those values has not been checked against the timing-adapter documentation.
- Consequence: any comparison of TA states (including `evidence/ta_ab/`) that used NPU cycles only is a statement
  about counted cycles, not elapsed time. Profile-1 conclusions (MLEK condition) are unaffected by this experiment.

CPU cycles are DWT at a nominal, unverified 50 MHz (S0-8 NOT_AVAILABLE).

## Limit found afterwards (2026-11-02, step 2a′, `ta_semantics.md`)

Both profiles set TA MODE bit 0 ("enable dynamic clocking to avoid underrun", core-platform `timing_adapter.h`). This
experiment varied only the limit and latency fields; `TA_NOT_EXPLAINS` does not cover the dynamic-clocking bit.
