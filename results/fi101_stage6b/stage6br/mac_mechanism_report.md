# MAC 처리 메커니즘 분석 (Phase 1) — `POSTHOC_EXPLANATORY`

조건: 보드 측정은 모두 TA profile 1, 이미지 `70090f1`이다. 이번 단계에서 새로 측정한 것은 없다. 수치는 `mac_padding_analysis.csv`, 판정은
`stage6br_summary.json`(`python3 host/analysis/stage6br.py run results/fi101_stage6b/stage6br`)에 있다.

자료의 종류를 구분한다.
- **실측**: MAC_ACTIVE, MAC_DPU_ACTIVE. 측정 RUN 4회 모두 같은 정수였다.
- **정적 계산**: ublock 수, Cin 조각, 예측값. 입력은 command stream의 커널별 OFM 크기와 Vela의 ublock·IFM block이다.
- **사후 가설**: 아래 H·D 식 전부.
- **미검증 추론**: "하드웨어가 이렇게 동작한다"는 해석. 이 문서는 이것을 주장하지 않는다.

## 1. 결과 요약 (공식 표본 14개)

공식 표본은 다음 14개다.
- Stage 4K 1×1: Cin 16, 32, 40, 48, 64
- Stage 4C2: Cin 128
- 6B-B: 기준 형상과 VALID 7개

UNSTABLE 3개는 `EXPLORATORY`로 따로 셌다.

| 가설 | 식 | 일치 | 판정 | 탐색 표본 |
| --- | --- | ---: | --- | ---: |
| H1-G (지시서) | ⌈H,u_h⌉⌈W,u_w⌉⌈Cin,32⌉⌈Cout,16⌉/1024 | 9/14 | **CONTRADICTED** (Cin16·32·64·128, G25) | 2/3 |
| H1-C16 | H·W·⌈Cin,16⌉⌈Cout,16⌉/1024 | 4/14 | CONTRADICTED | 2/3 |
| H1-U8 | Σ U_k · ⌈Cin/8⌉ | 7/14 | CONTRADICTED | 1/3 |
| H1-U16 | Σ U_k · ⌈Cin,16⌉/8 | 10/14 | CONTRADICTED | 2/3 |
| **H1-UC** | Σ_k U_k · Σ_조각 max(32, ⌈x,16⌉)/8 | **14/14** | **CONSISTENT_WITH_OBSERVATIONS** (가장 가까운 경쟁 가설과 갈리는 표본 2개) | 3/3 |

- U_k는 커널 k의 OFM ublock 수다: ⌈H_k/u_h⌉·⌈W_k/u_w⌉·⌈D_k/u_c⌉.
- 조각(x)은 Cin을 IFM block 깊이(DepthFirst 64, PartKernel 16) 단위로 나눈 것이다.

H1-UC에서 구성요소를 하나씩 빼면 모두 `CONTRADICTED`가 된다. 네 요소가 다 있어야 14개를 설명한다.

| 제거한 요소 | 일치 | 틀리는 표본 |
| --- | ---: | --- |
| 공간 ublock padding | 12/14 | G25 (25×5), G40 (7×7, ublock 1×4) |
| 커널별 Cout slice (전체 Cout 사용) | 7/14 | Stage 4 전부(Cout 96 = 커널 16 + 80) |
| IFM 깊이 조각 (Cin 전체를 한 번에) | 11/14 | Cin 32 PartKernel, G25, G57 |
| 조각당 최소 32채널 | 10/14 | Cin 16·32 PartKernel, G25, G57 |

판정은 `CONSISTENT_WITH_OBSERVATIONS`지만 **검증된 일반 법칙은 아니다.**
- 이 식은 같은 데이터에서 탐색으로 찾았다(계약 서두에 밝힘).
- 식에 들어 있는 상수가 실제로 갈린 적이 거의 없다.
  - min 32는 조각 4, 12, 16, 20에서만 작동했다.
  - IFM block 깊이는 16과 64 두 값뿐이다.
  - ublock은 2×2×32, 2×4×16, 1×4×32 세 종류다.
- **전향적 검증이 필요하다**(`next_experiment_contract_draft.md` E1).

## 3. Stage 4K 640/768과 G09 1024의 관계 (지시 2.2)

H1-UC로 쓰면 N_MAC/MAC_ACTIVE = 1024 × (공간 활용) × (Cout 활용) × (Cin 활용)이다(정적 계산).

| 사례 | 공간 | Cout | Cin | 곱 × 1024 |
| --- | --- | --- | --- | ---: |
| 4K Cin40 | 1 | 96/128 (16 + 80 → 32 + 96) | 40/48 | 640 |
| 4K Cin48 | 1 | 96/128 | 48/48 | 768 |
| 4K Cin64 | 1 | 96/128 | 64/64 | 768 |
| 4C2 Cin128 | 1 | 96/128 | 128/128 | 768 |
| G09 | 1 | 384/384 | 64/64 | 1024 |

- 지시서가 지적한 대로 Cin 64는 32의 배수인데도 768이었다. Cin padding만으로는 설명되지 않는다.
- 이 식에서 768의 원인은 Cout 쪽이다.
  - Vela가 Cout 96을 커널 두 개(16과 80)로 나눴다.
  - 각 slice가 ublock 깊이 32 단위로 올라가서 32 + 96 = 128이 된다.
  - 이 커널 분할은 command stream에서 직접 읽은 사실(정적)이다.
- 640은 여기에 Cin 40 → 48(16 단위) 손실이 더해진 값이다.
- G09는 공간, Cout, Cin 모두 손실이 없어 1024다.
- 따라서 Stage 4K에서 1×1 처리율로 읽었던 768은 이 형상 계열(24×24×96)의 Cout 분할에 따른 값으로 설명된다. 하드웨어 상수라는 근거는 없다.
  이것은 `POSTHOC_EXPLANATORY`이며, 커널 분할을 바꾼 형상으로 전향적으로 확인해야 한다.
- 지시서 2.2에서 Cin128을 "Stage 4K"로 적었는데, 이 데이터는 Stage 4C2(`results/fi101_stage4c2`)의 같은 형상 계열 측정이다.

## 4. 예외 형상 G25·G53 (지시 2.3)

| 항목 | G25 (VALID) | G53 (UNSTABLE, 탐색) |
| --- | --- | --- |
| OFM / ublock / OFM block | 25×5×140 / 2×2×32 / 14×6×96 | 8×8×268 / **2×4×16** / 8×8×96 |
| 공간 가장자리 | 25 → 26, 5 → 6 (활용 125/156) | 없음 |
| Cout 정렬 | 140 → 160 (ublock 깊이 32) | 268 → 272 (ublock 깊이 **16**) |
| Cin 조각 | 64+64+**12** (12 → 32) | **44** 하나 (44 → 48) |
| traversal / 커널 수 / 메모리 | DepthFirst / 1 / Sram→Sram | DepthFirst / 1 / Sram→Sram |
| H1-G(전역 Cin32·Cout16)와 다른 점 | Cout을 16이 아니라 ublock 깊이 32로 올림 | Cin 44를 32 단위(64)가 아니라 48로 올림 |

- 6B-B에서 "단일 식으로 9/11"이라고 했던 것은 Cin과 Cout의 올림 단위를 전역 상수로 둔 탓이었다.
- H1-UC에서는 올림 단위가 형상에서 나온다. Cout은 그 형상의 ublock 깊이(G25 32, G53 16)로, Cin은 조각 규칙(44 → 48)으로 올린다. 두 형상 모두 잔차가 0이다.
- 이것은 같은 데이터로 식을 고른 결과다. G53이 ublock 깊이 16인 유일한 공식 후보였다는 점이 원인이라고 단정하지 않는다.
  - ublock 2×4×16은 공식 표본에 하나도 없다. G53·G56은 UNSTABLE이다.
  - 따라서 u_c = 16 경우는 **탐색 표본으로만** 맞았다.

## 5. DPU 가설 (지시 2.4)

| 가설 | 일치 | 판정 |
| --- | ---: | --- |
| D-R (지시서) DPU/MAC = ⌈Cin,8⌉/⌈Cin,32⌉ | 8/14 | **CONTRADICTED** |
| D-U16: Σ U_k·Σ ⌈x,16⌉/8 | 13/14 | CONTRADICTED (G57) |
| D-U8: Σ U_k·Σ ⌈x,8⌉/8 | 11/14 | CONTRADICTED |
| D-PW: 조각 ≤ 8이면 ⌈x,8⌉, 아니면 ⌈x,16⌉ | 14/14 | **INSUFFICIENT_EVIDENCE** |

- D-R이 틀린 표본: Cin 32·40·48(4K, 기준), G12, G52. 예를 들어 Cin 48은 48/64 = 0.75로 예측되지만 실측은 1.0이다.
- D-PW와 D-U16을 가르는 공식 표본은 G57 하나뿐이다(조각 4). 그래서 계약 규칙에 따라 판정 불가다.
- 관측된 DPU/MAC < 1(0.5, 0.75, 0.9)은 모두 MAC 쪽 "조각당 최소 32"가 작동한 표본에서만 나왔다.
  - Cin 16(PartKernel 조각 16): MAC 4, DPU 2
  - G25(조각 12): MAC 4, DPU 2
  - G57(조각 4): MAC 4, DPU 1
  - 즉 DPU는 이 최소값을 적용받지 않는 것처럼 보인다(사후 기술).
- MAC 식과 DPU 식을 같은 하드웨어 메커니즘이라고 가정하지 않는다. 두 카운터의 정의는 TRM 설명 이상으로 확인하지 않았다.

## 6. 새 탐색 기록 (`EXPLORATORY`, 판정에 넣지 않음)

- Stage 4K 3×3 PartKernel Cin 16: MAC_ACTIVE 10,368 = 576 ublock × 18 = 9 탭 × 2 사이클. 1×1 PartKernel의 조각당 최소 4사이클과 달리, 탭당 2사이클(16/8)이다.
  - 3×3에서는 조각당 최소 32 규칙이 같은 방식으로 작동하지 않는 것으로 보인다. 확인하지 않았다.
