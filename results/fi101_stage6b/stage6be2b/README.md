## Vela 예측 오차에 대해 말할 수 있는 범위

- **CONV 단독**: Vela의 지연 민감도(Δ, 비율)가 실측과 사전 기준 안에서 맞는다.
  - Vela 식에서 이 그래프는 DRAM read 지연 한계(total = dram_ac ∝ 지연)다. 보드도 거의 비례로 반응했다(R 1.94 대 2.00).
  - 절대 오차는 +21.6 % → +17.8 %로 비슷하게 남는다.
- **G12 (A2)**: 보드 증가량이 Vela의 1.96배다. 그러나 비율은 같다(1.589 대 1.567).
  - 보드 실행시간은 두 지연에서 모두 Vela의 약 1.9배다(절대 오차 +88 % → +91 %).
  - 초과분이 고정 비용이 아니라 지연과 함께 커진다는 뜻이다. E2A에서 A군 고정 비용 가설이 반증된 것과 같은 방향이다.
  - Vela는 G12의 지연 증가분을 ADD(그래프 입력 DRAM 읽기) +21,562와 Conv +8,528로 나눈다. 보드에서 어느 연산이 얼마나 늘었는지는 측정하지 않았다(연산별 PMU 없음).
- 결론: Vela의 지연 민감도는 **Conv 단독 그래프에서는 맞고, A2 그래프에서는 절반 정도로 작다.** A2의 큰 절대 오차(+90 %)는 지연을 바꿔도 비율로 유지된다.
- E2A의 원인 판정(CAUSE_UNRESOLVED)은 자동으로 바꾸지 않는다. 다만 "A2 그래프의 초과 실행시간은 EXT 읽기 지연에 비례해 커지는 성분을 포함한다"는 새 근거가 생겼다.

## 남은 가설과 후속 통제 실험 (실행 미승인)

- A2와 단독 Conv는 래퍼(ADD 2개), Conv IFM/OFM 배치(Sram 대 Dram), 그래프 입력 경로가 함께 다르다. 이번 결과로 이 차이를 개별 원인에 배정하지 않는다.
- 다음에 분리할 변수 후보는 다음 두 가지다.
  1. 같은 Conv 형상에서 **메모리 배치만** 바꾼다(Dram/Dram 대 Sram/Sram, 래퍼 없음).
  2. 같은 배치에서 **래퍼만** 넣고 뺀다.
- 지연 2점 측정이라 선형성은 검증하지 않았다.
- Vela가 A2에서 반영하지 않은 지연 의존 성분 후보는 다음과 같다. 모두 가설이고 미검증이다.
  - 실행 중첩 가정(max 대신 합)
  - 가중치 스트림 정체(WD_STALLED)
  - ADD의 DRAM 읽기 패턴

## 한계

- 조건마다 boot 하나다. boot 사이의 독립 반복이 없어서 통계적 인과를 주장하지 않는다.
- L1000 boot는 L500보다 시간상 뒤다. drift는 시작 때 REF로 한 번만 확인했다. 다만 L500 두 구성이 이전 boot(411, 429)를 재현했다.
- 지연 변수 하나다. 메모리·파이프라인의 개별 기여를 분리하지 않았다.
