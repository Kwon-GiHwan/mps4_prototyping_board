Vela 시스템 가정도 통일하고 MAC별 재컴파일: 공통 시스템 가정 아래 대상 MAC 변경과 그에 따른 컴파일러 최적화 효과

후자도 컴파일 결과가 달라지므로 “물리 MAC 배열 크기만의 효과”와 완전히 같지는 않습니다. 그러나 현재보다 훨씬 명확한 통제 비교입니다.

256 산출물을 512 하드웨어 설정에서 그대로 실행하는 식으로 바이너리를 억지로 통일할 필요는 없습니다. 각 대상에 유효한 프로그램을 유지해야 합니다.

2.4 두 번째 역전은 별도입니다

이번 X4는 256→512의 첫 역전을 설명하는 실험입니다. 1024→2048의 두 번째 역전까지 설명한 것은 아닙니다.

논문이 첫 전이만 심층 분석한다면 그 범위를 명시하면 됩니다. RNNoise ladder 전체의 비단조 원인을 설명하려면, 두 번째 전이에서도 최소한 같은 방식의 지연 민감도와 나머지 구성 변화를 확인해야 합니다.

공개 MLEK 문서는 BWCAP이 트랜잭션 단위로 동작하며 정확도가 제한된다고 명시합니다. cap에 도달하거나 초과한 뒤 다음 pulse까지 추가 트랜잭션을 막는 방식이고, burst 길이에 맞춰 cap을 설정하는 방법을 권합니다.

따라서 100% 초과는 다음으로 설명될 수 있습니다.

가능성	확인할 내용

그러므로 1.08을 1.00으로 잘라 버리거나 임계값 허용오차만 늘려서 처리하지 마세요. 초과가 모델의 허용 동작인지 먼저 설명해야 합니다.

또한 113k 전송시간과 105–112k 측정 사이클이 가까운 것은 보조 근거이지만, 전자는 같은 cap 공식에서 나온 값입니다. 독립적인 두 측정이 맞아떨어진 것으로 세면 안 됩니다.

3.3 U85의 RULED_OUT은 지금 너무 강합니다

전체 추론 평균 이용률이 0.19–0.45라고 해서 대역폭 제약을 완전히 배제할 수는 없습니다.

논리적으로 가능한 경우는 다음과 같습니다.

일부 구간에 전송이 집중되어 그때만 cap에 걸림

여러 포트의 합산 평균은 낮지만 특정 포트에 요청이 집중됨

지연이나 낮은 요청 동시성 때문에 평균 전송률이 낮으면서, 전송 구간에서는 대역폭 제한도 작용함

따라서 현재 판정은:

전체 추론 평균에서 외부 경로의 지속적인 집계 대역폭 포화를 뒷받침하지 않는다.

정도가 맞습니다.

RULED_OUT에 가까워지려면 같은 프로그램·지연·요청 제한에서 BWCAP을 완화했는데도 성능이 달라지지 않는지 확인해야 합니다. 그 경우에도 배제 범위는 평가한 프로그램과 설정입니다.

3.4 쓰기 미수집과 포트 집계를 확인해야 합니다

U65에서 하한으로 처리한 것은 맞습니다. U55도 AXI1_WR을 수집하지 않았으므로 같은 논리를 검토해야 합니다.

Shared_Sram의 외부 영역이 읽기 전용으로 사용된다는 컴파일러 설정은 근거가 됩니다. 공개 Vela 설정도 이 모드의 외부 영역을 read-only로 가정합니다. 다만 실제 배치와 실행 경로까지 확인하지 않고 쓰기 트래픽을 측정한 결과 0이었다고 표현해서는 안 됩니다. 
GitHub

U85는 MAC별 포트 집계도 주의해야 합니다. PMU 집계값을 단일 포트 cap으로 나누는지, 전체 포트 예산으로 나누는지를 맞춰야 합니다. 공개 시스템 설정에서도 512·1024·2048의 사용 포트 수가 달라집니다. 
GitHub

3.5 진행 중인 U55 BWCAP 변주가 핵심 검증입니다

25/50/100/200/0 실험은 적절합니다. 해석에서는 다음을 확인하세요.

기본 50에서 100·200으로 완화할 때 사이클이 감소하는가, 그리고 동일 프로그램의 외부 전송량은 대체로 유지되는가가 우선입니다. 그렇다면 “기본 TA bandwidth cap이 실행 비용을 제한한다”는 개입 근거가 됩니다.

다만 BWCAP=0은 bandwidth quota 무제한이지 TA 전체 비활성화가 아닙니다. 지연·요청 제한·PULSE_OFF는 별도로 남습니다. 
GitHub

대역폭과 지연의 공동 제약까지 구분하려면 대표 MAC 하나에서 다음 2×2가 유용합니다.

	기본 지연	완화한 지연
기본 BWCAP	기준	지연 완화 효과
완화한 BWCAP	대역폭 완화 효과	두 제약을 함께 완화한 효과

이는 전 모델 추가 스윕이 아니라 U55/RNNoise의 병목 분류를 확인하는 소규모 후속 실험입니다.

그리고 TA cap 계산과 Vela INI 주석의 일치는 설정 간 일관성 확인이지 독립적인 성능 검증이 아닙니다. 두 설정이 같은 레퍼런스 시스템을 표현하도록 작성되었을 가능성을 배제할 수 없기 때문입니다.
