# A10 — 후속 검증 가설 H1′·H2′·H3′ (매니저 검토 반영본, 결과 아님)

**2026-09-14, 정정 커밋.** 초판의 오류를 매니저 검토(manager_log.md)로 바로잡았다: (i) H1′의 "하한"에
실측 C(0)를 쓰면서 기울기는 절편 자유 회귀에서 가져온 불일치, (ii) 기울기 k를 "직렬 외부 왕복 횟수"로
확정한 과잉 해석, (iii) H2′의 잔여 비용을 가중치 전송에 귀속한 성급함, (iv) H3′의 ublock 공간 면적
증가 서술 오류([1,4,8]→[2,2,16]은 면적 4→4, 형상과 채널 폭이 바뀐 것)와 단일 H×W 임계 조건.
여기 적힌 수치는 기존 측정(A5·A6·A8)에서 계산한 서술값이며, 세 가설은 **미검증 후속 가설**이다.
검증 실험은 별도 계약과 승인 전에는 실행하지 않는다.

## 왜 가설을 다시 세우나

- 요인 1(SRAM 대역폭): U55·U65 전 구성에서 SRAM 경로 전송률이 TA 허용치의 90% 미만 → 전체 평균
  포화 미관측. 제한 효과 자체를 배제한 것은 아니며 U85는 포트 집계 미확인으로 미결.
- 요인 4(DWConv): 모델 간 상관 없음(rho −0.08), 연산 단위로도 DW가 Conv보다 덜 빨라지지 않음
  (512/256 중앙값 0.667 vs 0.778) → 일관된 확장 불이익 미관측. 일반적 설명으로는 지지되지 않음.

## H1′ — RNNoise의 실행 비용은 외부 메모리 지연 설정에 민감하며, 민감도와 지연 0의 잔여 비용은 MAC 구성별로 다르다

**관측 (X4 캠페인 A·D, 산출물 고정, 읽기 지연 L·쓰기 L/2 함께 변경).** 실측 0-지연 값과 증분으로 적는다.
선형성은 강제하지 않는다.

| RNNoise U85 | 실측 C(0) | C(base) − C(0) | 회귀 절편 a | 회귀 기울기 k (실효 지연 민감도) | 적합 구간 |
|---|---|---|---|---|---|
| 256 MAC (base 250) | 21,086 | 15,000 | 15,461 | 98.2 | 0–1,000 |
| 512 (base 500) | 16,086 | 39,000 | 11,011 | 92.1 | 0–2,000 |
| 1024 (base 500) | 11,086 | 38,000 | 8,686 | 84.9 | 0–1,000 |
| 2048 (base 500) | 11,086 | 43,000 | 9,086 | 92.0 | 0–1,000 |

- k는 "TA EXT 읽기·쓰기 지연 설정 묶음에 대한 실행 사이클의 실효 민감도"다. 직렬 외부 왕복 횟수가
  아니다. 겹침이 전혀 없는 모델에서도 k = N_read + ½·N_write 꼴이고, 실제로는 outstanding
  요청·버퍼링·연산-전송 겹침이 있으므로 더 복잡하다.
- 256 MAC의 구간별 기울기는 40 → 80 → 104 → 108로 증가한다. 전 구간에 같은 대기 횟수가 작용한다고
  읽을 수 없다.
- MAC별 적합 구간이 다르므로(512만 2,000 포함) 기울기의 MAC 간 비교는 공통 구간(0–1,000)으로 다시
  맞춘 뒤에만 가능하다. 현재 말할 수 있는 것: **RNNoise에서는 MAC 구성을 바꿔도 외부 지연 설정에
  대한 민감도가 유지된다.** "MAC과 무관"은 아니다.
- 기본 지연에서 지연 제거의 순효과(256: 15,000)는 잔여 21,086보다 작다. "지연 항이 항상 하한보다
  크다"는 틀렸다. 1024→2048 역전 5,000 중 3,500(Δk×500)은 같은 데이터의 계수로 같은 데이터를 설명한
  것이라 독립 검증이 아니다.

**후속 검증 (새 계약 필요):**
1. 지연 민감도가 직렬화된 메모리 의존성과 어떤 관계인지 — 명령 스트림의 DMA 명령 수는 보조 근거일
   뿐(명령 1 ≠ AXI 트랜잭션 1) → stall/DMA 대기 카운터 계측이 성립해야 한다(S4 재계약).
2. 읽기 지연과 쓰기 지연을 분리 변주해 각각의 기여를 나눈다.
3. KWS·AD에서 같은 구조가 나오는지(지연 변주 2셀씩). 그 전까지 "소형 모델"로 일반화하지 않는다.

## H2′ — Wav2Letter의 지연 0 조건에서 남는 실행 비용에는 외부 메모리 전송 대역폭 제약이 기여할 수 있다

**관측.** Wav2Letter U85에서 EXT 지연을 0으로 두어도 기본 사이클의 99%(256)·92%(512)가 남는다. 이것이
직접 뜻하는 것은 "기본 구성에서 TA EXT 읽기·쓰기 지연을 제거하는 것만으로는 대부분의 비용이 줄지
않는다"까지다. 지연 0은 메모리 접근 비용 전체를 0으로 만드는 설정이 아니며(BWCAP·pulse·요청 수 제한은
남음), 잔여 비용의 후보에는 계산·가중치 해제·메모리 전송·내부 버퍼/파이프라인이 모두 있다. 외부 접근도
가중치만이 아니라 IFM·OFM·중간 데이터를 포함한다.

두 가설로 나눈다.
- H2′-a **외부 대역폭 제약**: Wav2Letter U85-512에서 EXT_BWCAP을 완화하면 사이클이 줄어든다. 줄면 "해당
  구성에서 EXT bandwidth cap의 제한 효과가 관측됐다"까지 말할 수 있다.
- H2′-b **가중치 streaming 귀속**: 잔여 비용 중 가중치 전송의 몫은 별도 확인이 필요하다. 외부 트래픽에서
  가중치·재사용·반복 전송을 분리해야 하고, 가중치는 인코딩·재배열되어 전송되므로 원본 크기가 전송
  바이트가 아니다(A6: 인코딩 후 0.99–1.75배). U55/RNNoise의 BWCAP 효과(A8)는 이 귀속을 대신 검증하지
  않는다.

## H3′ — 작은 공간 크기와 출력 형상의 블록 매핑 특성이 특정 MAC 전이의 비용 변화와 연관될 수 있다

**관측 (A6, U85 256→512 분리 가능 연산).** 비용이 증가한 연산의 OFM 공간 크기(H×W) 중앙값 36,
감소한 연산 256; 채널은 136 vs 96. YOLO 제외 64 vs 256, VWW 64 vs 256. 연산 종류(DW/Conv) 비율은
양쪽에 같다.

**정정.** ublock [1,4,8]→[2,2,16]은 공간 면적 4→4이며 높이 1→2, 너비 4→2, 채널 폭 8→16으로 **형상과
채널 폭이 바뀐 것**이지 공간 면적이 커진 것이 아니다. 256 스케줄에 [1,2,16]을 쓰는 연산이 있다면 따로
비교해야 한다. 또 H×W만으로는 형상 불일치를 판정할 수 없다(1×36과 6×6은 면적이 같지만 높이 2 블록에
대한 경계·패딩이 다르다). 중앙값 36 vs 256이 "공간 크기 ≤ 4"라는 임계 조건을 뒷받침하지도 않는다.
연산 종류 비율이 같다는 것만으로 종류와 무관하다고 결론 내리지 않는다. "작은 공간 크기"와 "ublock 변화"를
같은 원인의 두 얼굴로 합치는 것도 아직 이르다.

**후속 검증:** H·W·C별 경계 조건, 실제 ublock/block 구성, tile 수를 기준으로 한 검사(기존 스케줄
덤프·differential 표로 가능, 새 측정 불필요) — 연산 종류·모델·채널·TA 조건을 통제한 뒤에도 연관이
유지되는지. 입력 해상도 변형 실험은 연산량·activation·DMA·배치가 함께 바뀌므로 보조 근거로만.
