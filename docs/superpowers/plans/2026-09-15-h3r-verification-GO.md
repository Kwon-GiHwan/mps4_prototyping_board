# GO — H3-R 보강 실험 실행

## 0. 목적과 승인 범위

H3-R의 목적은 기존 H3에서 확인된 두 통제 문제를 해결하는 것이다.

1. 형상별 calibration으로 최종 INT8 양자화 조건이 달랐던 문제
2. relaxed 조건에서도 MAC 간 EXT_MAXR/MAXW가 달랐던 문제

이번에는 계획서 작성에서 멈추지 말고 다음 순서로 진행한다.

계획·판정 규칙 커밋
→ 기준 모델 확인 및 파생 모델 생성
→ 모델·설정 검증
→ 첫 셀 qualification
→ 전체 실행
→ 분석
→ 보고서 및 최신 발표자료에 반영

승인 범위:
- 파생 INT8 모델 생성
- Vela 컴파일 및 TA 설정별 펌웨어 빌드
- 아래 126 arm의 FVP 실행
- 기존 방식의 별도 출력 검증 빌드
- 분석 스크립트·보고서·발표자료 갱신

기존 H3, H13, X4 및 frozen evidence는 수정하거나 덮어쓰지 않는다.
H3-R은 별도 캠페인으로 저장하고 기존 결과와 병기한다.
종료된 S4 stall 계측은 다시 실행하지 않는다.

승인 범위 안에서는 단계마다 추가 GO를 요청하지 않는다.
다만 모델 유효성·출력·실효 설정 게이트가 실패하거나 실험 범위 변경이 필요하면,
실패 증거를 보존하고 해당 문제의 영향을 받는 후속 실행을 중단한다.

## 1. 기준 자료와 계획

- 현재 저장소의 H13 계획서·결과·분석기·H3 모델 및 실행 기록을 기준으로 한다.
- 다른 버전의 논문이나 과거 외부 리뷰의 수치를 섞지 않는다.
- 계획서에 A8로 H3-R의 목적, 조건, 판정식, 비교 범위, 승인 내용을 기록한다.
- 새 실행값을 얻기 전에 계획과 판정 코드를 커밋한다.
- 기준 커밋, 도구 버전, FVP 바이너리, 입력 파일과 기존 evidence manifest를 기록한다.

이번 실험은 기존 논문의 §3.4에 해당하는 실행 구조 분석을 보강하는 것이다.
RQ·목차를 새로 만들거나 기존 결론을 미리 확정하지 않는다.

## 2. 모델 생성 — 최종 INT8 비형상 요소 고정

### 2.1 기준 모델

연산 종류별로 기존 H3의 6×6 INT8 모델을 기준으로 재사용한다.

- 1×1 Conv
- SAME-padding 3×3 Conv
- SAME-padding 3×3 DWConv

기준 모델이 없거나 사용할 수 없다면 임의로 다시 calibration하지 말고
그 이유와 대체 방법을 먼저 보고한다.

### 2.2 파생 형상

각 기준 모델에서 IFM/OFM의 공간 shape와 직접 관련된 shape metadata만 바꾼다.

면적 36의 9형상:

1×36, 2×18, 3×12, 4×9, 6×6,
9×4, 12×3, 18×2, 36×1

총 3종 × 9형상 = 27모델.

새로운 calibration·재양자화·가중치 재생성은 하지 않는다.

### 2.3 G1′ — 형상 간 비형상 요소 동일성

연산 종류별 기준 모델과 모든 파생 모델을 필드 단위로 비교한다.

반드시 동일해야 하는 것:
- 최종 INT8 가중치 버퍼
- 최종 bias 버퍼
- 입력·출력·가중치·bias의 양자화 레코드
  - scale
  - zero-point
  - quantized dimension
- 연산 종류·연산자 버전·입출력 연결
- stride·dilation·padding·활성화 등 연산 옵션
- 채널 수 및 기타 비형상 설정

허용하는 차이:
- IFM/OFM 공간 shape
- shape_signature 등 해당 shape와 직접 연동되는 metadata
- 재직렬화 때문에 달라지는 FlatBuffer 오프셋

최종 정수 버퍼를 추출하여 SHA-256을 계산한다.
양자화 전 float 가중치의 해시를 이 검사의 대용으로 사용하지 않는다.
모델 파일 전체 SHA는 shape가 다르므로 달라도 정상이다.

### 2.4 기능 확인

- TF 인터프리터로 모든 파생 모델의 로드·실행·출력 크기를 확인한다.
- 연산 종류별로 공통 입력 벡터를 만들고 각 H×W에 reshape하여 사용한다.
- 입력 바이트와 입력 정책을 고정·기록한다.
- 동일 형상의 모델에서는 MAC·TA 변경 전후 출력 동일성을 검사한다.
- 서로 다른 형상의 출력이 같아야 한다는 조건은 두지 않는다.
- 인터프리터 실행 성공을 NPU 출력 동일성 검증으로 대신하지 않는다.

3×3 SAME-padding은 형상에 따라 경계·패딩 비중이 달라질 수 있으므로
이를 모델 metadata와 결과 해석에 명시한다.

## 3. 실험 조건

FVP 바이너리·버전, MLEK, Vela, 컴파일러, 메모리 모드,
arena/cache, 입력, 실행·수집 방법은 기존 H3와 동일하게 유지한다.

Vela system_config는 기존 H3의 MAC별 설정을 유지하고 기록한다.
따라서 이 실험을 "물리 MAC 배열 크기만 다른 실험"이라고 부르지 않는다.

TA 조건은 다음 세 가지다.

| 조건 | 대상 | 설정과 목적 |
|---|---|---|
| base | 27모델 × 256/512 | 기존 H3의 MAC별 low/mid 설정을 그대로 사용. 양자화 고정 후 기존 패턴 재현 여부 확인 |
| equalized | 27모델 × 256/512 | 두 MAC의 TA 실효 파라미터 전체를 동일하게 설정 |
| bridge_legacy_relaxed | DW 9모델 × 256/512 | 공통 양자화 모델에 기존 H3 relaxed 설정을 그대로 적용. MAXR/MAXW 동일화 효과를 분리하는 연결 대조군 |

### 3.1 equalized 설정

두 MAC 모두 다음을 적용한다.

- EXT_RLATENCY = 0
- EXT_WLATENCY = 0
- EXT_BWCAP = 0
- SRAM_RLATENCY = 0
- SRAM_WLATENCY = 0
- EXT_MAXR = 0
- EXT_MAXW = 0

나머지 TA 파라미터도 두 MAC에서 동일하게 고정한다.
기존 계획에서 관리하는 16개 값을 모두 명시적으로 전달한다.

- SRAM/EXT의 나머지 요청 제한
- MAXRW
- BWCAP
- PULSE_ON/OFF
- MODE 및 실제 적용에 관련된 설정

어떤 항목도 MAC별 자동 기본값에 의존하지 않는다.

EXT_PULSE_OFF는 기존에 완주가 확인된 값을 유지한다.
기존 timeout을 유발한 EXT_PULSE_OFF=0은 사용하지 않는다.

"무제한"은 해당 TA 요청 제한 또는 bandwidth quota가 해제됐다는 뜻으로만 쓴다.
NPU·버스·pulse 등 모든 제약이 사라졌다는 의미로 사용하지 않는다.

### 3.2 실효 적용값 검증

다음 연결을 확인한다.

명시한 -D 값
→ CMakeCache
→ generated TA header
→ 드라이버의 마스크·변환
→ 실제 적용되는 값

요청값과 적용값을 별도 컬럼으로 기록한다.
기존 MAXR 64→0 마스킹 확인 방식을 재사용한다.
헤더에 값이 같다는 사실만으로 적용값 동일성을 판정하지 않는다.

equalized는 두 MAC의 실효 TA 값 전체가 같아야 통과한다.

### 3.3 DW 연결 대조군

선택 제안이었던 "1×1 Conv equalized-24/12"는 이번에 실행하지 않는다.
그 대신 DW 9형상의 bridge_legacy_relaxed 18 arm을 실행한다.

연결 구조:

기존 H3 DW:
    기존 형상별 양자화 + 기존 relaxed

H3-R DW 연결 대조:
    공통 기준 양자화 + 기존 relaxed

H3-R DW 주 실험:
    공통 기준 양자화 + equalized

이를 통해 다음을 구분한다.

- 기존 양자화 조건을 공통 조건으로 바꾼 뒤 패턴이 유지되는가?
- 동일한 새 모델에서 MAXR/MAXW를 동일화하면 패턴이 달라지는가?

기존 H3 relaxed의 요청값·적용값을 정확히 재사용한다.
기억이나 "대략 같은 조건"으로 재구성하지 않는다.

| 구분 | arm 수 |
|---|---:|
| 27모델 × 2 MAC × base/equalized | 108 |
| DW 9모델 × 2 MAC × bridge_legacy_relaxed | 18 |

- arm당 stock FVP 3회: 총 378회
- 출력 검증 빌드는 별도로 집계

면적 64·256 및 MAC 1024·2048은 이번 범위에 포함하지 않는다.
그 범위의 기존 결론이 H3-R로 검증됐다고 서술하지 않는다.

## 5. 실행 게이트

기존 G1–G6을 기반으로 하되 합성 실험에 맞게 적용 범위를 명확히 한다.

| 게이트 | 검사 |
|---|---|
| G1 | 동일 모델·MAC·Vela 설정의 산출물이 TA arm 간 동일 |
| G1′ | 같은 연산 종류의 9형상에서 최종 가중치·bias·양자화·연산 옵션 동일 |
| 설정 게이트 | 요청 TA 값과 실효 적용값 일치, equalized의 MAC 간 전체 값 동일 |
| 반복 게이트 | 동일 arm의 AXF 및 측정 벡터가 3회 반복에서 동일 |
| 실행 게이트 | 추론 정상 완료, 필수 필드 존재, 오류·overflow 검사 |
| 출력 게이트 | 동일 형상의 모델에서 MAC·TA 변경 전후 출력 검증 |
| 보존 게이트 | 기존 evidence 무변경, 원시 UART·실행 명령·설정·해시 보존 |

주의:
- TA 변경으로 AXF가 달라지는 것은 정상이다.
- 모든 arm의 AXF를 과거 동결 AXF와 같게 요구하지 않는다.
- 정확히 동일한 과거 조건을 재현한 anchor만 과거 값과 비교한다.
- 필수 값 None을 0으로 대체하지 않는다.
- None == None으로 재현성 게이트를 통과시키지 않는다.
- 출력 검증은 별도 빌드에서 수행하고 성능 측정은 stock 경로에서 수행한다.
- 모델마다 출력이 다른 것은 정상이다. 동일 모델의 비교 대상 간 동일성을 검사한다.

첫 qualification은 본 매트릭스 안의 대표 셀로 수행한다.
게이트 통과 후 나머지를 실행한다.

가설과 반대되는 결과는 실패가 아니다.
게이트를 충족한 반증 결과는 그대로 보존·분석한다.

## 6. 수집 데이터

각 모델·MAC·조건·반복에 다음을 기록한다.

- model_id, op_type, H, W, C, area
- kernel, stride, padding, dilation
- 모델 및 최종 정수 버퍼·양자화 레코드 식별 정보

- 실제 ublock, OFM/IFM block, tile, traversal, launch 관련 정보
- encoded weight 크기와 memory allocation
- TA 요청값 전체와 실효 적용값 전체
- TOTAL, ACTIVE, derived IDLE
- SRAM_RD/WR, EXT_RD/WR
- 입력·출력 검증 결과
- 원시 UART 경로·SHA
- 실행 상태, 실패·재시도 사유

형상별 최종 Vela 스케줄이 달라지는 것은 관측 대상으로 기록한다.
스케줄 차이가 있음을 이유로 결과를 제외하지 않는다.

## 7. 사전 판정

기존 H3의 수식을 유지한다.

r = C512 / C256
scaling_efficiency = 1 / (2r)
spread = max(r) - min(r)

- SHAPE_EFFECT:
  같은 연산·면적·조건에서 spread ≥ 0.10

- MEMORY_SHAPE_INTERACTION:
  spread_equalized < 0.5 × spread_base

- TYPE_DEPENDENT:
  기존 계획서 §7의 연산 종류별 중앙값 비교식을 그대로 사용

이번에는 TOTAL과 ACTIVE 각각에 위 식을 적용하는 것을 측정 전에 명시한다.

- TOTAL: 기존 연구와 연결하는 주 분석
- ACTIVE: 사전에 지정한 병렬 분석
- 두 판정이 같으면 두 지표에서 유지되는 결과
- 다르면 METRIC_DEPENDENT로 별도 표시

ACTIVE를 TOTAL의 정답 대체물로 사용하지 않는다.
TOTAL 격자 1,000을 검증된 ±1,000 측정 오차로 해석하지 않는다.
결과를 보고 threshold를 바꾸지 않는다.

면적 36만 측정하므로 AREA_EFFECT의 새 검증은 하지 않는다.

연결 대조군에서는 기존 relaxed→equalized의 r·spread·사이클·traffic 변화를 보고한다.
새로운 임계값을 결과에 맞춰 만들지 않는다.

## 8. 반드시 답할 비교

### Q1. 양자화 고정 후 기존 패턴이 유지되는가?

기존 H3 base와 H3-R base를 비교한다.

- 1×1 Conv의 어떤 형상에서 역전·동률·개선이 발생하는가?
- 36×1·12×3 등 기존 특이 형상의 패턴이 유지되는가?
- 양자화 고정 전후 스케줄·encoded weights·traffic이 어떻게 달라지는가?

"기존 6개 역전이 그대로 나와야 성공"이라는 게이트는 두지 않는다.

### Q2. 동일한 모델에서 TA 조건을 바꾸면 무엇이 달라지는가?

H3-R의 base↔equalized를 비교한다.

- 각 MAC의 사이클 변화
- 256→512 비율 r의 변화
- 형상별 spread의 변화
- 메모리 traffic과 스케줄 대응

이 비교는 TA 설정 묶음의 개입 효과다.
여러 값을 함께 바꿨다면 지연·대역폭·동시성 중 하나만의 효과라고 쓰지 않는다.

### Q3. DW의 기존 relaxed 차이에 MAXR/MAXW 비대칭이 기여했는가?

공통 양자화 DW 모델에서 다음을 비교한다.

bridge_legacy_relaxed ↔ equalized

- 차이가 줄면: 요청 동시성 설정 묶음의 기여를 평가
- 차이가 남으면: 비대칭 제거 후에도 남는 차이를 기록
- 차이가 남았다는 이유만으로 "매핑 자체가 원인"이라고 확정하지 않음

MAC마다 어떻게 달라졌는지 함께 보고해,
어느 구성의 변화가 r·spread 변화를 만들었는지 드러낸다.

### Q4. 어떤 결론이 측정 지표에 의존하는가?

- TOTAL·ACTIVE 판정 일치/불일치 표
- 작은 사이클 차이가 있는 대표 사례의 원시값
- 이전 H3에서 지표에 따라 달랐던 결론이 이번에도 달라지는지

### Q5. 실제 block 매핑과 어떤 관계가 있는가?

H·W·C별 block, padding, tile, traversal 및 traffic을 연결한다.

- 같은 H×W라도 H와 W의 배치에 따라 경계 조건이 다른지
- 256 쪽 비용 증가인지, 512 쪽 비용 증가인지
- 형상 변경에 동반된 실행 구조가 무엇인지

단순 H×W/MAC 비율을 실측 PE 이용률로 부르지 않는다.
3×3 경계·패딩 효과를 특정 ublock 비효율로 자동 귀속하지 않는다.

## 9. 결과 해석 기준

다음 범위를 지킨다.

- 패턴 유지:
  "양자화 차이가 없어도 평가한 패턴이 나타났다."

- 양자화 고정 후 차이 감소:
  "기존 패턴은 양자화 조건 통제에 민감했다."
  모든 차이가 양자화 때문이라고 확대하지 않는다.

- 동일 모델에서 TA 변경 후 확장 비율 변화:
  "평가한 TA 설정 묶음이 확장 결과에 기여했다."

- equalized에서도 형상 차이 유지:
  "동일한 TA 실효 파라미터 조건에서도 형상별 차이가 남았다."
  물리 메모리 제약이 모두 사라졌다거나 매핑 원인이 확정됐다고 쓰지 않는다.

- 형상에 따른 차이:
  형상이 만드는 padding·메모리 접근·컴파일러 스케줄 변화까지 포함한 효과로 해석한다.
  특정 내부 유닛의 독립 효과로 좁히려면 별도의 직접 근거를 제시한다.

기존 결과를 지키는 것이 목적이 아니다.
새 통제 실험이 기존 설명을 반박하면 그 결과로 결론을 수정한다.

## 10. 산출물과 반영

별도 H3-R 디렉터리에 다음을 생성한다.

- 계획서 A8 및 기준 커밋
- model manifest와 G1′ 검증 결과
- 요청/실효 TA 매트릭스
- arm별·반복별 측정 CSV
- TOTAL/ACTIVE 지표 및 판정 대응표
- 기존 H3↔H3-R 비교표
- DW 연결 대조군 비교표
- 대표 스케줄·block·traffic 근거
- 원시 UART·출력 검증 자료
- 재생성 가능한 분석·그래프 스크립트
- 최종 결과 보고서

보고서는 다음 순서로 작성한다.

1. 원래 통제 문제
2. 실제로 고정·변경한 항목
3. 핵심 관측과 수치
4. 사전 예측과의 일치·불일치
5. TOTAL·ACTIVE 판정 차이
6. 기존 결론 중 유지·강화·수정·철회할 내용

완료 후 최신 발표자료의 형상·DW·ublock 관련 부분을 새 버전으로 반영한다.
기존 H3와 H3-R의 결과를 구분하고, 최신 덱의 실제 페이지 번호에 맞춰 수정한다.
기존 덱과 원본 데이터는 보존한다.

계획 확정 커밋과 결과 반영 커밋을 분리한다.

최종 보고에는 실행 arm 수·반복 수·게이트 결과·실패/재시도와 함께,
"두 통제 문제를 제거한 뒤 무엇이 남고 무엇이 사라졌는가"를 명확히 답한다.
