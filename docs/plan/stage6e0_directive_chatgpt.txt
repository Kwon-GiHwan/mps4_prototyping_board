Stage 6D에서 제안한 G_DF_EXT는 유효한 후보로 보존하지만, 현재 보드 측정은 승인하지 않는다.

목표는 실제 7개 MLEK 모델의 NPU_ACTIVE 및 Vela 예측 오차를 설명하기 위해, 기존 독립 연산 Characterization을 모델 실행과 연결할 수 있는 검증 방법을 확립하는 것이다.

신규 보드 실행, TA 변경, 펌웨어 배포, 기존 결과 수정은 승인하지 않는다.

1. 연구 질문

RQ-E1 — Compute Cost Attribution

독립 연산에서 측정한 MAC_ACTIVE와 실제 모델의 MAC_ACTIVE 사이에 발생하는 차이를 어떤 조건에서 설명할 수 있는가?

RQ-E2 — Execution Overlap

실제 모델의 연산 간 실행 중첩, 데이터 의존성 및 DMA 활동이 NPU_ACTIVE에 미치는 영향을 기존 계측과 실행 구조로 구분할 수 있는가?

RQ-E3 — Vela Fidelity

Vela의 연산별 Compute/SRAM/DRAM 비용과 실제 모델의 실행시간 오차를 연결할 수 있는 검증 가능한 방법이 있는가?

RQ-E4 — Model-Level Generalization

현재 Hardware Characterization의 적용 범위를 넓히는 것과 실제 모델 실행시간 설명력을 개선하는 것 중 어떤 연구 공백이 더 중요한가?

4. Phase 2 — AD 잔여 MAC_ACTIVE 분석

AD는 기존 Characterization Coverage가 높음에도 MAC_ACTIVE 예측 합이 모델 측정값보다 크게 작은 사례다.

따라서 우선 진단 대상으로 사용한다.

단, AD 하나의 문제에 연구 전체를 종속시키지 않는다.

다음 항목을 확인한다.

원본 모델의 Vela kernel 구성

DepthFirst / PartKernel 분포

Cin/Cout 및 OFM block

H1-UC 적용 가능 범위

모델 내부 연산과 독립 재구성의 차이

Weight/Scale 및 IFM/OFM 배치

Fused activation

Vela kernel 분할 및 실행 반복

TFLite N_MAC과 Vela mac_count의 차이

PMU 측정창과 실행 반복 수

독립 연산 계수 합산의 유효성

우선 기존 자료만으로 설명 가능한 차이를 확인한다.

특히 MAC_ACTIVE는 처리부가 활성화된 사이클이므로 연산별 실행 구간의 중첩이나 계측 경계가 존재할 경우 단순 합산이 가능한지 검증한다.

기존 Stage 2B에서 실패한 귀속 방식을 재사용하지 않는다.

설명되지 않은 차이를 임의로 Padding, DMA 또는 WD Stall에 귀속하지 않는다.

G_DF_EXT를 기존 후보로 평가하되, 높은 MAC Coverage 증가만으로 자동 선정하지 않는다.

새로운 형상 측정이 모델 전체 실행시간의 설명력을 개선하지 못한다면 해당 한계를 명시한다.

반대로 기존 하드웨어 Characterization의 적용 범위가 핵심 장애물이라는 근거가 확보되면 이를 정당한 후속 실험 대상으로 인정한다.

후속 실험은 하나만 권고한다.

10. Research Direction & Guardrails

본 연구의 장기 목표는 Ethos-U85 Hardware–Compiler Performance Analysis다.

다음 네 축을 균형 있게 유지한다.

Compute/Unit

MAC·DPU·AO·WD, PartKernel·DW·FC의 처리율과 실제 실행 조건.

Memory/Pipeline/AXI

데이터 공급, 재사용, Burst, 요청, 포트, 실행 중첩과 전체 실행시간의 관계.

Vela Compiler Fidelity

Compute/Memory 비용 모델의 정확도, 과대·과소예측 및 성능 변화의 방향과 크기.

Model-level Explainability

7개 MLEK 모델의 NPU_ACTIVE와 실행 효율 차이에 대한 설명력.

이번 Stage 6E-0은 새로운 하드웨어 측정을 무조건 추가하기 위한 단계가 아니다.

기존 독립 연산 Characterization과 실제 모델의 실행시간 사이에 존재하는 설명 공백을 검증 가능한 연구 질문으로 전환하기 위한 단계다.

H1-UC 외삽, SRAM 배치, AD 잔여 비용, F2 Vela 반례 등 특정 문제 하나에 지나치게 집중하지 않는다.

각 후속 실험은 다음을 명시해야 한다.

다만 이미 검증한 결과를 반복하거나, 특정 태스크의 세부 원인만 무제한 추적하지 않는다.
