1. G1 수정 원칙

기존 G1은 NPU_ACTIVE 중앙값의 차이가 ±1% 이내인지 검사했다.

그러나 기존 m7 측정 자체의 RUN 범위가 약 2.6%였으므로 이 기준은 측정 변동성을 충분히 고려하지 못했을 수 있다.

새 기준은 다음과 같다.

Delta = abs(median(B0) - median(m7))

Tolerance = max(0.01 × median(m7), range(m7) + range(B0))

G1_NPU_PASS = Delta <= Tolerance

여기서 range는 동일 조건의 측정 RUN에서 max-min으로 정의한다.

기존 m7의 원시 RUN을 사용한다.

Warm-up은 통계에 포함하지 않는다.

이 기준은 두 세션의 중앙값 차이에 대한 경험적 재현 허용 기준이며, 통계적 신뢰구간이나 실행 동등성의 증명으로 해석하지 않는다.

특히 range 기반 허용폭이 지나치게 커지면 실제 성능 차이를 놓칠 수 있다.

따라서 다음 검사를 필수로 추가한다.

두 측정 세션의 RUN 범위와 중앙값 차이를 모두 보고

새 기준의 실제 허용폭을 사전 계산

허용폭이 기존 실험에서 관측된 정상 변동을 넘어 과도하게 커지는지 검토

결정적 카운터의 정확 일치

출력 및 실행 구성 동일성

신규 세션 내부 측정 안정성

사전에 정한 안정성 기준을 초과한 신규 측정은 허용폭을 확대해 통과시키지 않는다.

boot 477의 측정값을 사용해 새로운 임계값을 최적화하지 않는다.

새 기준은 기존 m7의 독립적인 원시 측정 분포와 사전 정의한 계산식으로 고정한다.

8. Vela 정오표 반영

Stage 6E-0에서 확인한 Vela 비용 항목 혼용 문제를 명시적으로 반영한다.

다음 두 값을 구분한다.

cycles_npu

Vela의 NPU 관련 비용 항목.

cycles_total

Vela의 연산별 비용 추정 합계.

두 값을 동일한 값으로 취급하지 않는다.

기존 Stage 6-M, 6D, 6E-0의 원본 결과와 판정은 유지한다.

새 분석에서는 각 값의 정의와 출처를 명시한다.

모델 수준 Board/Vela ratio를 보고할 때 어떤 Vela 비용 항목을 분모로 사용했는지 반드시 표시한다.

기존 cycles_npu 기반 수치와 새 cycles_total 기반 수치를 같은 시계열의 직접 비교값으로 사용하지 않는다.

필요하면 두 값을 병렬로 제시하되 공식 예측 정확도 판정에 사용하는 지표를 사전에 동결한다.

10. Research Direction & Guardrails

본 연구의 목표는 Ethos-U85 Hardware–Compiler Performance Analysis다.

연구는 다음 네 축을 균형 있게 진행한다.

Compute/Unit — MAC·DPU·AO·WD, PartKernel·DW·FC

Memory/Pipeline/AXI — 데이터 공급, 요청, Burst, 포트, 실행 중첩

Vela Fidelity — 비용 모델 오차와 성능 변화의 방향·크기

Model-level — 7개 MLEK 모델의 NPU_ACTIVE와 효율 설명력

이번 Amendment B는 기존 X3의 계측 재현성 기준을 수정하기 위한 것이다.

새로운 연구 가설이나 측정 대상을 추가하지 않는다.

기존 결과를 소급 변경하지 않는다.

그룹 귀속에 성공하면 모델 수준 설명력 분석으로 연결한다.

실패하면 계측 한계를 기록하고 전체 연구의 다른 미해결 질문으로 복귀한다.

H1-UC, SRAM 배치, AD 잔차, PMU_MASK 등 특정 태스크 하나를 무제한 추적하지 않는다.

다음 실험을 설계할 때는 반드시 기존 결과와의 차별성, 연구적 기여, 종료 조건 및 전체 연구 복귀 경로를 명시한다.
