1. 수정할 안정성 기준

기존 GS는 그룹별 NPU_ACTIVE의 RUN 간 range가 중앙값의 5% 이하여야 한다는 조건을 적용했다.

그러나 기존 전체 모델 측정에서도 약 1,000~2,800사이클의 절대 변동이 관측되었으며, 상대 5% 기준은 작은 그룹 계측창에서 실패 가능성이 높았다.

그룹 창 B2–B4의 Pass A NPU_ACTIVE에 한하여 다음 기준을 적용한다.

range = max(measured_runs) - min(measured_runs)

GS_limit = max(0.05 × median_NPU_ACTIVE, model_range_cap)

GS_PASS = range <= GS_limit

모델별 cap:

KWS: 2,423 cycles

AD: 2,596 cycles

이 값은 기존 m7 측정의 세트별 range 최댓값으로 고정한다.

기존 원시 자료와 SHA256을 통해 값의 출처를 검증한다.

다음 규칙을 유지한다.

B0/B1의 기존 안정성 기준은 변경하지 않는다.

그룹 창 B2/B3/B4에만 신규 기준을 적용한다.

MAC_ACTIVE와 MAC_DPU_ACTIVE의 기존 안정성 및 정확성 검증은 유지한다.

Pass B/C의 기존 안정성 검증은 유지한다.

모델별 cap은 보드 결과를 보고 조정하지 않는다.

새 기준의 정상·오류·경계 조건을 테스트한다.

이번 변경은 boot 489를 확인한 뒤 설계한 전향적 Amendment라는 사실을 명시한다.

기존 boot 489를 새 기준으로 재판정하지 않는다.

해석상 주의사항

새 기준은 모델 전체 계측에서 관측된 절대 변동 폭을 그룹 계측창의 허용 기준으로 사용하는 경험적 기준이다.

그룹 창에서도 동일한 변동 메커니즘이 발생한다는 사실은 입증되지 않았다.

따라서 GS PASS를 그룹 NPU_ACTIVE의 높은 정밀도가 검증되었다는 의미로 해석하지 않는다.

그룹별 다음 항목을 반드시 보고한다.

중앙값

최소값 및 최댓값

절대 range

상대 range

적용된 GS_limit

상대 허용폭

Vela 오차 또는 그룹 간 차이가 측정 변동보다 충분히 큰지

측정 변동이 연구 질문의 판별에 필요한 차이보다 크다면, GS PASS이더라도 해당 정량적 가설은 INSUFFICIENT_EVIDENCE로 판정한다.

10. Research Direction & Guardrails

장기 연구 목표는 Ethos-U85 Hardware–Compiler Performance Analysis다.

연구는 네 축을 균형 있게 유지한다.

Compute/Unit — MAC·DPU·AO·WD, PartKernel·DW·FC의 처리율과 형상 특성

Memory/Pipeline/AXI — 데이터 공급, 재사용, Burst, 요청, 포트, 실행 중첩

Vela Fidelity — 예측 오차의 크기와 방향, 컴파일러 비용 모델의 한계

Model-level — 7개 MLEK 모델의 NPU_ACTIVE 및 효율 설명력

이번 Amendment C는 그룹 계측의 안정성 문제를 해결하고 기존 X3 연구 질문을 최종 검증하기 위한 것이다.

새로운 하드웨어 연구 질문이나 측정 대상을 추가하지 않는다.

실험 종료 후에는 다음을 수행한다.

KWS·AD의 설명력 변화 정리

X3 방법론의 유효 범위와 한계 기록

기존 7개 모델 연구 공백 재평가

H1-UC, SRAM 배치 및 PMU_MASK에 대한 반복 추적 종료

미해결 Unit/AXI 및 Vela Fidelity 질문의 중요도 재평가

새로운 실험은 기존에 검증된 결과를 반복하는 것이 아니라 실제 새로운 Hardware Characterization 또는 Vela Fidelity 근거를 제공해야 한다.

특정 문제 하나가 전체 연구의 진행을 장기간 지연시키지 않도록 한다.
