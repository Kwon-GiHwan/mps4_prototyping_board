1. 연구 목적

이번 실험의 핵심은 실제 모델의 실행 비용을 그룹별로 관측할 수 있는 방법을 검증하는 것이다.

세 가지를 구분한다.

Compute Attribution

완료 장벽으로 구분한 그룹의 MAC/DPU/AO/WD 활동이 실제 모델 전체 활동과 어떤 관계를 갖는가?

Execution Serialization

커널 실행을 직렬화하면 NPU_ACTIVE와 Unit 활동이 어떻게 변화하는가?

Vela Fidelity

직렬화 조건의 그룹별 실행 비용은 Vela의 연산별 비용 예측과 얼마나 일치하는가?

이 실험은 원본 모델의 연산별 실행시간을 직접 복원하는 실험이 아니다.

직렬화된 모델은 원본과 다른 실행 스케줄을 가진다.

그룹의 연산 집합이 겹치거나 누락되지 않는지 검증한다.

B2/B3/B4는 동일한 직렬 실행 스트림을 사용하고 PMU 측정 구간만 변경해야 한다.

그룹별 스트림 자체가 달라지면 동일 실행의 비용 분해로 인정하지 않는다.

마지막 그룹의 실행이 측정 종료 전에 완료되는가?

PMU_MASK 명령 처리 시점과 실제 Unit 활동 시점이 구분되는가?

그룹별 계수 합산이 구조적으로 유효한가?

장벽 및 명령 처리 오버헤드는 어떻게 처리되는가?

합계가 모델 전체 계수와 일치한다는 이유만으로 연산별 귀속이 정확하다고 판정하지 않는다.

독립 연산의 알려진 활동량을 이용한 별도 검증을 요구한다.

4. Phase 1 — 사전 가설 및 판정 동결

Stage 6E-0의 기존 가설을 유지한다.

H-S: MAC Schedule Invariance

원본과 직렬 실행의 MAC_ACTIVE가 ±1% 범위에서 일치하는가?

불일치하면 직렬화가 계산부의 활동에도 영향을 주는 것으로 판정한다.

H-P: Group Partition Validity

그룹별 PMU 계수 합과 직렬 모델 전체 계수가 ±1% 범위에서 일치하는가?

이것은 필요한 일관성 검사이지만, 단독으로 귀속 정확성을 증명하지 않는다.

H-K: KWS Independent Reference

KWS op0 및 기존 DF EXACT 그룹의 활동이 독립 측정 또는 검증된 H1-UC 예측과 일치하는가?

기준:

독립 F5: MAC_ACTIVE 26,090

DF EXACT: H1-UC 11,700

기존 계약의 ±1% / ±5% 기준 유지

독립 형상과 모델 내부 실행 구성이 달라질 경우 비교 가능성을 별도로 판정한다.

H-A1 / H-A2: AD Residual

AD의 MAC_ACTIVE 잔여 차이가 검증되지 않은 연산군에 집중되는지, 검증된 연산군에서도 발생하는지 확인한다.

H-O: Serialization Effect

원본과 직렬 실행의 NPU_ACTIVE 차이를 측정한다.

Serialization_Delta = NPU_ACTIVE_serial - NPU_ACTIVE_original

양수이면 직렬화로 실행시간이 증가한 것이다.

그러나 증가분 전체를 원래 실행의 순수 커널 간 중첩 이득이라고 단정하지 않는다.

장벽 자체의 비용, 명령 처리, DMA 스케줄 및 버퍼 동작 변화가 포함될 수 있다.

H-V: Vela Group Fidelity

직렬 실행 그룹의 NPU_ACTIVE와 대응하는 Vela 연산별 예상 비용 합을 비교한다.

Vela 연산과 PMU 그룹의 대응이 불명확한 경우 정량 비교를 수행하지 않는다.

모든 판정 규칙은 보드 결과를 보기 전에 동결한다.

그룹별 측정창이 의도한 범위를 측정하지 못한다면 후속 boot를 진행하지 않는다.

13. 종료 조건

이번 X3는 최대 10 boot로 종료한다.

그룹별 PMU 귀속이 검증되면 KWS·AD의 모델 수준 설명력을 재평가한다.

귀속이 실패하면 실패 원인을 기록하고 기존 Stage 2B의 한계를 유지한다.

귀속 실패를 이유로 즉시 다른 PMU 방식이나 추가 모델 실험을 시작하지 않는다.

G_DF_EXT, F2 Vela 반례, AO-1, WD-1/2는 기존 미해결 항목으로 보존한다.

14. Research Direction & Guardrails

장기 연구 목표는 Ethos-U85 Hardware–Compiler Performance Analysis다.

다음 네 축을 균형 있게 유지한다.

Compute/Unit: MAC·DPU·AO·WD, PartKernel·DW·FC

Memory/Pipeline/AXI: 데이터 공급, 재사용, 요청, Burst, 포트, 중첩

Vela Fidelity: 비용 예측 오차의 원인과 성능 변화 방향·크기
